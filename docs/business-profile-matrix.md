# Матриця профілів бізнесу та навігації

## Принцип

Профіль магазину не повинен створювати окрему копію CRM. Продажі, склад, закупівлі, фінанси, клієнти, постачальники й звіти — спільне ядро для всіх видів торгівлі. Профіль додає або прибирає лише спеціалізовані робочі інструменти.

Поточна версія має п'ять профілів: `general_retail`, `grocery`, `auto_parts`, `electronics`, `online_store`.

## Матриця функціональності

| Профіль | Основні робочі розділи | Спеціальні можливості | Що не повинно показуватися |
|---|---|---|---|
| Роздрібна торгівля | Каса, продажі/повернення, клієнти, товари, склад, закупівлі, постачальники, фінанси, звіти | Універсальні одиниці виміру, штрихкоди, категорії, послуги | Підбір за авто, каталог запчастин, OE та аналоги |
| Продуктовий магазин | Спільне ядро торгівлі, закупівлі, залишки, фінанси | Партії та терміни придатності — коли хоча б один товар має режим `expiry` або `batch` | Автомобільний каталог та OE/аналоги; серійний облік не показується без товарів із таким режимом |
| Автозапчастини | Спільне ядро торгівлі | Підбір за авто, каталог деталей, OE-номери, аналоги/кроси, автомобілі клієнтів, пошук за парою бренд + артикул | СТО — тимчасово вимкнене для релізу |
| Електроніка та техніка | Спільне ядро торгівлі | Серійні номери / IMEI — коли в асортименті є серійно-обліковувані товари; партії за потреби | Автомобільний каталог, OE та аналоги |
| Інтернет-магазин | Товари, замовлення, залишки, клієнти, закупівлі, фінанси, відправлення | Обробка замовлень і відправлень у межах наявних модулів та ліцензії | Автомобільний каталог, OE та аналоги |

## Спільні розділи

Усі профілі використовують єдині правила для:
- каси, продажів, повернень і відкладених чеків;
- товарів, категорій, штрихкодів, одиниць виміру та послуг;
- закупівель, постачальників, приймання та складських рухів;
- клієнтів, взаєморозрахунків, каси/банку й фінансових звітів;
- користувачів, ролей, друкованих форм, ліцензії та резервного копіювання.

Доступність PRO-функцій додатково визначається ліцензією. Профіль бізнесу не повинен обходити тарифні обмеження.

## Правила чистого меню

1. Автомобільні розділи видимі тільки профілю «Автозапчастини».
2. Приховування посилання недостатньо: прямі URL автомобільних екранів також блокуються сервером.
3. «Партії та терміни» показуються, лише якщо є активні товари з режимом обліку `batch` або `expiry`.
4. «Серійні номери / IMEI» показуються, лише якщо є активні товари з режимом `serial`.
5. Django Admin не є робочим модулем магазину; посилання на нього бачать лише користувачі з прапорцем Django staff.
6. СТО залишається вимкненим у релізному профілі, навіть якщо старий тарифний ключ містить відповідне доповнення.
7. Не створювати окремі вкладки для функцій, які вже є частиною іншого робочого процесу. Наприклад, пошук постачальників має залишатися в єдиному потоці підбору/закупівлі, а не дублюватися окремим пунктом без самостійного сценарію.

## Межі поточної реалізації та наступні етапи

Це не означає, що CRM уже має повноцінний галузевий функціонал кожного профілю:
- Для продуктового магазину потрібні додаткові перевірки списання прострочених партій, попередження про терміни, інвентаризація за партіями та сценарії повернення постачальнику.
- Для електроніки потрібні гарантійні строки, прив'язка IMEI/серійного номера до продажу та історія гарантійного звернення.
- Для інтернет-магазину потрібні окремі інтеграції з сайтом/маркетплейсами, синхронізація замовлень, оплат і статусів доставки. Наявний профіль сам по собі не створює інтернет-вітрину.
- Для загальної роздрібної торгівлі потрібні налаштовувані атрибути товару та варіанти (розмір, колір тощо), якщо цього вимагатимуть реальні сценарії.

Не приховувати ці прогалини фальшивими вкладками: спочатку реалізувати й протестувати процес, потім додавати його в меню.

## Дизайн навігації

Поточна бічна навігація згрупована за робочими процесами, але лишається довгою. Наступний UX-етап — зменшити кількість постійно видимих пунктів, залишити щоденні дії на першому рівні, а рідкісні звіти/довідники/налаштування згрупувати всередині відповідного розділу. Не створювати паралельні вкладки для того самого процесу.
