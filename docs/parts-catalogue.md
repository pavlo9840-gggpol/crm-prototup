# Каталог підбору автозапчастин

## Що входить
- VehicleMake, VehicleModel, VehicleVariant — нормалізований довідник транспорту.
- CatalogPart і CatalogPartNumber — логічна деталь та її брендований артикул; не дублюють складський Product і прайс SupplierItem.
- PartFitment — доказ застосовності артикула до моделі/модифікації, з джерелом і роками.
- CatalogSource / CatalogImportRun — ліцензія, походження даних, версія та історія імпортів.
- Сторінка /catalogue/ — пошук за авто, артикулом, OE-номером і назвою.

## 1. Завантажити довідник авто
Після розгортання коду й застосування міграцій виконай:

    python manage.py migrate
    python manage.py import_vehiclesdb --dry-run
    python manage.py import_vehiclesdb

Імпортер за замовчуванням використовує версію VehiclesDB, закріплену в URL:
https://cdn.jsdelivr.net/gh/vehiclesdb/vehiclesdb@v2026.10.3/dist/vehicles.json

Відкритий шар VehiclesDB ліцензований CC BY 4.0; атрибуція є умовою використання. У CRM показується посилання Vehicle data by VehiclesDB. Перевіряй актуальні ATTRIBUTION.md і SOURCES.md upstream перед оновленням джерела. Цей імпорт містить марки й моделі, а не артикули, OE-номери, двигуни чи сумісність усіх запчастин.

Імпорт повторно запускається без дублікатів за канонічними slug/ID. Не використовуй --url для джерела, ліцензія якого не перевірена.

## 2. Імпорт дозволеного каталогу деталей
CSV UTF-8 від постачальника або з відкритою ліцензією може містити колонки:

    brand,sku,name,category,oe,oe_brand,make_slug,model_slug,kind,year_from,year_to,engine_code,fitment_notes,source_id,verified,description

Мінімально обов'язкові brand,sku. Щоб створити застосовність, також передай make_slug,model_slug, які вже є в довіднику. verified приймає true/1/yes/так; встановлюй його лише для даних, які дійсно перевірені джерелом.

Приклад:

    python manage.py import_parts_catalog ./licensed-parts.csv --source "Назва джерела" --url "https://example.org/dataset" --license "Назва ліцензії" --attribution "Обов'язкова атрибуція" --dry-run

Після перевірки звіту повтори команду без --dry-run.

Команда не змінює залишки/ціни і не створює товарів у Product. Нормалізована пара бренд+артикул є унікальною. Повторний імпорт не створює повторний CatalogPart, OE-зв'язок або застосовність. Конфлікт уже наявного брендованого артикула не переназначається мовчки.

## Обмеження й правила якості
1. Довідник автомобілів не доводить сумісність запчастини. PartFitment з'являється лише з дозволеного джерела або перевіреного імпорту.
2. Відсутність fitment означає «немає даних», а не «не підходить».
3. Спільна назва чи схожий артикул не роблять деталі аналогами. OE та CrossRef мають зберігати походження; ручне підтвердження має перевагу.
4. Нормалізація SKU прибирає розділові знаки. Якщо конкретний бренд має значущі символи, їх потрібно перевірити перед масовим імпортом, щоб не злити різні артикули.
5. Перевіряй розмір, джерело, умови ліцензії, атрибуцію та дату версії до імпорту. Не копіюй каталоги TecDoc або інші захищені бази без дозволу.
